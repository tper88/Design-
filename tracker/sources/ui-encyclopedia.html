How to use this

1 Find the part

Browse the tabs or type what you're after into the search box. Every card shows a live, working example — not a screenshot. Click them, they all respond.

2 Add it to the prompt basket

The "+" button on each card drops its description into the basket (bottom right). Collect 5–15 things your tool should be made of.

Anatomy of a good request

what separates a prompt that works

Weak prompt

Missing everything that decides the outcome: the data, the layout, the style, how it gets used.

The model guesses your columns, invents data, picks a random style. You get a demo, not a tool.

Strong prompt

Five ingredients: what it is, what data, which parts, which style, how it's used.

Build a single-file HTML tracker for tax queries. Data loaded from Excel via SheetJS; columns: ID, country, client, status, deadline, owner. Four KPI cards with count-up at the top, then a filter bar of chips plus a live search box, then a sortable table with statuses as coloured badges and a progress bar. Light/dark toggle, minimal corporate style, state saved to localStorage. Must run from a file, offline, in Edge.
The rule for today: AI can't read your mind, but it does know names. "KPI card with a delta badge and a sparkline" is a specific thing the model recognises — "a nice tile with a number on it" is a lottery. This whole encyclopedia is just a list of names.

A chart is an answer, not decoration. Decide the question first ("which country is growing fastest?"), then pick the chart type. Below: what to use when, and what to draw it with.

Bar chart

Comparing sizes across categories. The default and safest choice. Sort the bars descending — an unsorted bar chart wastes its own advantage.

Line / area chart

Reading an Excel file (SheetJS)

The file is parsed in the browser; nothing reaches a server. That is usually the argument that settles the data-security conversation.

<script src="https://cdn.sheetjs.com/xlsx-0.20.2/package/dist/xlsx.full.min.js"></script>

const input = document.getElementById('file');

input.addEventListener('change', async (e) => {
  const file = e.target.files[0];
  const buf  = await file.arrayBuffer();
  const wb   = XLSX.read(buf);
  const ws   = wb.Sheets[wb.SheetNames[0]];

  // array of objects: key = column header
  const rows = XLSX.utils.sheet_to_json(ws, { defval: '' });

  if (!rows.length) return showError('The sheet is empty');

Exporting the visible rows to CSV

The detail that matters: we export visibleRows, the data after filtering — what the user is actually looking at.

function exportCSV(visibleRows, name = 'export') {
  const cols = Object.keys(visibleRows[0]);
  const esc = v => '"' + String(v ?? '').replace(/"/g, '""') + '"';

  const csv = [
    cols.join(';'),
    ...visibleRows.map(r => cols.map(c => esc(r[c])).join(';'))
  ].join('\n');

  // BOM so Excel renders accented characters correctly
  const blob = new Blob(['\uFEFF' + csv], { type: 'text/csv;charset=utf-8' });
  const a = Object.assign(document.createElement('a'), {
    href: URL.createObjectURL(blob),
    download: name + '_' + new Date().toISOString().slice(0,10) + '.csv'
  });
  a.click();
}
CSV export with semicolons and UTF-8 BOM, date in the filename, filtered rows only.

Remembering state (localStorage)

Filters, dark mode and column widths survive closing the tab. A small thing that stops the tool being irritating.

const KEY = 'tracker.settings';

const save = (state) =>
  localStorage.setItem(KEY, JSON.stringify(state));

const load = () => {
  try { return JSON.parse(localStorage.getItem(KEY)) ?? {}; }
  catch { return {}; }   // a corrupted entry must not break the app
};

const state = { country: 'all', mineOnly: false, theme: 'dark', ...load() };
Persist state (filters, sorting, theme) in localStorage under one key, read in try/catch.

Filtering and sorting in one place

The pattern: one source of data, one function computing the view, one function redrawing. Without it, a tool starts drifting apart around the third feature.

let data = [];                  // source of truth — never mutated
let view = { search:'', country:'all', sort:'deadline', dir:1 };

function computeView() {
  const s = view.search.toLowerCase();
  return data
    .filter(r => view.country === 'all' || r.country === view.country)
    .filter(r => !s || Object.values(r).some(v =>
        String(v).toLowerCase().includes(s)))
    .sort((a,b) =>
        String(a[view.sort]).localeCompare(String(b[view.sort]),
          undefined, { numeric: true }) * view.dir);
}

function refresh() {         // called after EVERY filter change
  const v = computeView();
  renderTable(v); renderKPI(v); renderCharts(v);
}
Architecture: one data source, one computeView(), one refresh() redrawing table, KPIs and charts.

Print and PDF styles

Without this, the printout includes buttons, menus and a dark background eating toner. Three lines turn a tool into a document.

@media print {
  .sidebar, .filters, button, .no-print { display: none !important; }
  body  { background: #fff; color: #000; font-size: 11pt; }
  .card { break-inside: avoid; border: 1px solid #999; }
  table { page-break-inside: auto; }
  tr    { page-break-inside: avoid; }
  thead { display: table-header-group; }  /* header on every page */
  @page { margin: 14mm; size: A4 portrait; }
}

Round 1: single file, demo data, fully clickable, simple — refinement comes next.

Round 2 Fix what annoys you

Open it, use it for a minute, write down the three things that irritate you. Send them as three separate named changes — that's what the vocabulary is for.

Round 2: three named changes, nothing else touched, one line of explanation each.

Round 3 Make it survive Monday

The unglamorous layer: empty state, error message when the file is wrong, print styles, saved filters, mobile. This is what separates a demo from a tool people keep using.

Round 3: empty state, file error message, print styles, saved filters, mobile.

Pick a brief

or bring your own spreadsheet

Brief A — Deadline board

A team list of cases with due dates. Must answer one question in under three seconds: what is at risk this week? Suggested parts: KPI cards, status badges, filter chips, sortable table, overdue alert.

Brief B — Monthly volumes

A recurring report someone currently rebuilds by hand each month. Suggested parts: Excel import, bento grid, bar and line charts, range segmented control, print layout.

Brief C — Team handbook

Procedures nobody reads because they live in a 40-page document. Suggested parts: scrollytelling or sticky contents, accordion, stepper, search, tooltips for definitions.

Before you show it to anyone

a 60-second check

EmptyClear all filters — does it explain what happened, or just go blank?
Wrong fileLoad a file with a missing column — does it say which one?
PhoneNarrow the window to a phone width — does anything fall off the screen?
KeyboardTab through it — can you see where the focus is?
PrintCtrl+P — is it a document, or a screenshot of a dark app?
ExportFilter, then export — does the file contain the filtered rows only?
ReloadRefresh the page — are your filters and theme still there?
